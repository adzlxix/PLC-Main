PLC-Main code audit — 2026-09-14

FIXED
1. Kits.csv Line IDs were being inferred by pandas as floats because the CSV contains blank separator rows.
   Example: Line 1 loaded as "1.0" while the menu selected "1".
   Result: production incorrectly reported "No products found in Kits.csv for Line 1."
   Fix: shared identifier normalization added and applied to Kits, Production, Runtime, Equipment, Demand, Finished Goods, and Line Settings paths.

2. String cleanup order in production/runtime loaders used astype(str) before fillna(), which can turn blanks into literal "nan" strings.
   Fix: fillna("") now happens before string conversion.

3. Manual production saved line runtime before confirming that a valid product could be selected.
   Result: orphan runtime records could be created after a failed/cancelled product selection.
   Fix: product is now selected first; runtime is recorded only after a valid product is chosen.
   The issued-label workflow similarly validates the BOM before writing runtime.

REVIEW NOTE
- The application writes multiple CSV ledgers during a production transaction. A power loss or write failure between those file writes can theoretically leave a partial transaction (for example PROD saved but a later inventory/FG write failing). This is an architectural reliability limitation of a multi-CSV system rather than the Line 1 bug. A future improvement would be atomic transaction/rollback handling or migration to SQLite/PostgreSQL.
